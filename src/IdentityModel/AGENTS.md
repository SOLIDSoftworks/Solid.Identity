# WS-* protocol libraries

- Keep each protocol's entities and serializers in its own `Protocols.<Protocol>` project. Do not put WS-Addressing, WS-Federation, WS-Policy, WS-Security, WS-SecureConversation, or XML Encryption implementation in `Protocols.WsTrust`.
- Keep shared XML helpers, serializer interfaces, the serialization context, and protocol constants (including element and attribute names) in `Protocols.WsStar`. Constants may live there even when their entities and serializers live in a protocol-specific project.
- Reference the project that owns an entity or serializer when composing protocols. For example, WS-Policy references WS-Addressing for endpoint references; WS-Trust references the protocol projects it consumes. Do not introduce a dependency from a protocol project back to WS-Trust or a cycle through `Protocols.WsStar`.
- Preserve existing public namespaces when moving types unless a deliberate API change is required. Align new types with their protocol namespace; WS-SecureConversation types use `Solid.IdentityModel.Protocols.WsSecureConversation`.
- Implement new XML serialization through `ProtocolSerializer` and `IProtocolSerializer<T>` where applicable. Select the namespace from `WsSerializationContext`, check element names and namespaces when reading, and write namespace-qualified attributes such as `wsu:Id` correctly. Preserve extension XML when the protocol permits open content.
- When integrating with WS-Trust, keep WS-Trust envelope and request/response serialization there; delegate child protocol tokens and elements to their owning serializer. Leave unfamiliar token XML intact when it is not a recognized protocol element.
- Give every protocol project a matching `.tests/IdentityModel.Protocols.<Protocol>.Tests` project. Test each protocol's wire format, supported versions, optional fields, invalid input, and read/write behavior independently. Add WS-Trust integration tests when a protocol element appears inside a trust message.
- Validate with `dotnet build src/Solid.Identity.sln --no-restore` and `dotnet test src/Solid.Identity.sln --no-build --no-restore` across the configured .NET target frameworks. Review the solution and project-reference graph when adding a project.

## WS-* serializer pattern

Use `Protocols.WsStar/WsSecurityExampleSerializer.cs` as the detailed reference for serializers of inner-text values, entities with known children, and open-content entities. It is an illustrative, non-compiled project content file; adapt its placeholder types and names to the protocol specification. Follow the intended pattern below rather than copying mistakes in the example (in particular, assert the actual entity's element name and write attribute values).

- Derive each protocol serializer from `ProtocolSerializer` and implement `IProtocolSerializer<T>` for every entity it supports. Override `GetProtocolConstants` to return the corresponding constants from `WsSerializationContext`, `CreateContext(string ns)` to resolve supported namespace versions and populate the applicable context constants, and `SupportedEntities` to list **all** entities exposed by the serializer. Use the owning protocol's element and attribute constants from `Protocols.WsStar` in real serializers.
- For each entity, explicitly implement both `ReadEntity` overloads, both `TryReadEntity` overloads, and `WriteEntity`. The overloads without a context derive it with `CreateContext(reader)`; the others forward the supplied context. Route these entry points through the entity-specific methods rather than duplicating parsing or writing logic.
- Provide a `protected virtual TryRead<Entity>(reader, serializer, context, out entity)` extension point. Compare both `reader.LocalName` and `reader.NamespaceURI` against the expected element and the namespace from the context **before consuming the reader**; on mismatch, return `Out.False(out entity)`. On a match, call `XmlAttributeDescriptor.ReadAttributes(reader)`, construct the result with `Create<Entity>(context, attributes)`, read its contents, set the out parameter, and return `true`.
- Provide a `protected virtual Create<Entity>(context, XmlAttributeDescriptor[] attributes)` extension point for constructing and populating the entity, including support for derived entity types. Match known attributes by local name **and namespace**, using the namespace appropriate to each attribute (for example, `context.SecurityUtility.Namespace` for `wsu:Id`). Do not treat an attribute in another namespace as the known attribute.
- Provide a private `Read<Entity>(reader, serializer, context)` wrapper for `ReadEntity` that calls `AssertReader(reader, <that entity's element name>, context)` before calling `TryRead<Entity>`. `TryRead<Entity>` is the non-throwing element/namespace probe used when reading children; the asserting wrapper is for a required entity.
- For an element containing only inner text, call `ReadNode(reader, result, ReadValue)` and read its value with the XML reader method appropriate to the value's type. For an element containing children, call `ReadNode(reader, serializer, context, result, Read<Entity>ChildNode)`. Make the child-node method `protected virtual`, try each expected child in turn, and assign recognized children to the entity. Use this serializer's `TryRead<Child>` methods for children it owns; delegate children owned by another protocol serializer to `WsSerializer` where applicable.
- For a closed entity, skip unmatched child elements with `reader.Skip()` and only map attributes defined by its contract. For an `XmlOpenItem`, place attributes not recognized by their local name and namespace into `AdditionalXmlAttributes`, and handle unmatched child elements with `ReadAdditionalXmlElement(reader, entity)` so that extension XML is retained.
- Provide a `protected virtual Write<Entity>(writer, entity, serializer, context)` extension point. Call `WsUtils.ValidateParamsForWriting`, write the start element with the context's prefix and namespace, emit applicable known attributes with their correct namespaces and **values**, write known children using this serializer's `Write<Child>` methods and externally owned children via `serializer.WriteEntity`, then write the end element. Check optional values before writing them. For `XmlOpenItem`, also call `WriteXmlOpenItemAttributes` after known attributes and `WriteXmlOpenItemElements` after known children to preserve extension XML.
- Keep reading and writing symmetric for each supported version and entity shape. Test element/attribute namespaces, inner-text values, known-child handling, unknown-child behavior for closed and open entities, extension XML round trips, and optional fields in the owning protocol's test project.
